# Verification

Run `npm run verify` after `npm ci` and `npm run install:apps`.

The suite includes reference-engine invariants, source-provenance checks, session
replay and tamper rejection, compact-probe checks, migration compatibility,
Memory Weather engine/field/projection/demo tests, React-wrapper compatibility,
TypeScript checks, production builds, and repository-owned ASCII text checks.

## Migration evidence

Baseline records were generated by executing the historical code at commit
`1ab947e0cb75afaf0e7ecad11a8aa5e02b510ebc`. All 101 retrieved source files matched
their declared Git blob hashes before work began. The numerical baseline generator
also checks the SHA-256 source manifest before importing that source.

- 72 reference-engine runs: two numeric seeds, six input modes, four individual
  mechanism removals, all enabled, and all disabled; 96 ticks per run.
- 108 Memory Weather runs: two seeds, six input modes, seven individual mechanism
  removals, all enabled, and all disabled; 96 ticks per run.
- Four coupled Memory Weather runs: coupling on/off and both update orders;
  64 ticks per pair.
- Total: 17,792 individual state steps.

For each step, SHA-256 of a structured numerical record must match exactly.
The records cover state vectors, coherence, inputs, updates, smoothing, history,
memory summaries, event timing and numeric payloads, relevant counters, and
diagnostics. Final state vectors are also compared directly.

The successor weather runs additionally serialize and hydrate at tick 48, testing
continuation across its new replay schema against the original numerical sequence.
Labels, IDs, source references, and diagnostic hashes are excluded from numerical
records because those are intentional migration changes. They have separate schema,
pin, fixture, and compatibility checks.

The fixtures are regression evidence for the declared cases, not a proof of
equivalence for every possible input and not a task-performance benchmark.

## Reproduce baseline generation

Keep the historical checkout outside the active successor repository:

```bash
git clone https://github.com/donaldtuttle/qoft-calculus.git ../qoft-calculus-reference
git -C ../qoft-calculus-reference checkout 1ab947e0cb75afaf0e7ecad11a8aa5e02b510ebc
node --experimental-strip-types scripts/record-upstream-baseline.mjs ../qoft-calculus-reference
git diff --exit-code -- tests/fixtures/upstream-numerical.json
```

Tests never regenerate the fixture. A changed fixture requires an explicit review
of its verified source and generation procedure.

Browser validation and the exact commands executed for this migration are recorded
in RELEASE_CHECKS.md. GitHub-hosted CI and deployment are separate from local tests.
